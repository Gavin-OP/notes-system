## Anti-Patterns Verdict

**LLM assessment:** Not generic AI slop in the note shell — it reads as a standard Ant Design app with custom overrides. The inconsistency is **internal**: career/profile pages imported a second design language (dashed borders, soft gradients, oversized display labels, infinite bounce) that never reconciled with the restrained note layout. Purple (`#722ed1`) and dual blues act as rogue accents outside the Ant primary system.

**Deterministic scan (scoped CSS, 4 warnings):**
- `bounce-easing` ×2 — `ExploreCareersPage.css:47`, `UserProfilePage.css:489`
- `side-tab` ×2 — `UserProfilePage.css:115`, `AssistantWorkspace.css:129`

**Browser comparison:** Careers/profile use `#f5f5f5` page canvas + gradient dashed CTAs; note layout uses Ant container tokens via inline `--content-bg` and white content cards. Side-by-side they feel like different products.

## Overall Impression

The codebase has no shared token layer. `ConfigProvider` only swaps light/dark algorithms — it does not seed colors, spacing, radius, or motion. Admin CSS correctly references `var(--ant-color-bg-layout)`; learner note chrome and career pages hardcode parallel palettes. Unifying tokens and deleting duplicate button CSS would collapse most visible drift without touching flows.

## What's Working

1. **Dark mode coverage** — Note chrome, layout sider, and assistant dock include `[data-theme="dark"]` blocks; effort is real even if values are duplicated.
2. **Note reading typography** — `MarkdownRenderer.css` keeps prose hierarchy restrained; completion button styling matches `NotePage.css` (same blue/green pair).
3. **Admin shell alignment** — `admin.css` consumes Ant CSS variables; closest to the target pattern for the rest of the app.

## Priority Issues

### [P0] No shared design tokens — hardcoded colors everywhere
- **Why it matters:** DESIGN.md calls for color roles, spacing, radius, motion duration tokens. Grep shows `#1677ff`, `#1890ff`, `#722ed1`, `#4096ff`, `#1668dc` scattered across 15+ CSS files with no single source. Admin uses `--ant-color-*`; note/career pages ignore it.
- **Fix:** Add `src/styles/tokens.css` (or extend `ConfigProvider theme.token`) with roles: `--color-primary`, `--color-surface`, `--color-border`, `--space-*`, `--radius-*`, `--duration-*`. Replace hex in note chrome and career pages first.
- **Suggested command:** `/impeccable extract src/styles`

### [P1] Dual primary blues — Ant legacy vs Ant v5 default
- **Why it matters:** `NoteHeader.css` uses `#1890ff` (Ant v4 default); note chrome, layout, careers use `#1677ff` (Ant v5). Hover/focus rings split across both. Header icons feel subtly “off” next to sidebar progress blue.
- **Fix:** Bind all custom CSS to `var(--ant-color-primary)` / `colorPrimary` token from ConfigProvider; remove `#1890ff` entirely.
- **Suggested command:** `/impeccable colorize note header and custom buttons`

### [P1] Rogue purple accent breaks single-accent rule
- **Why it matters:** DESIGN.md: one primary accent. `#722ed1` appears in quote blocks (`AssistantWorkspace.css`, `UserProfilePage.css`), micro-course gradient CTA (`NotePage.css`), and profile hover inset — a third color family beside Ant blue and success green.
- **Fix:** Map quotes/highlights to primary tint or a dedicated `--color-accent-muted` derived from primary hue; remove purple gradient on micro-course button.
- **Suggested command:** `/impeccable quieter note and profile quote accents`

### [P1] Career/profile CTA pattern diverges from note shell
- **Why it matters:** `ExploreCareersPage` and `UserProfilePage` share nearly identical blocks: dashed `rgba(22,119,255,0.35)` border, 16px radius, vertical gradient, 22px display type, infinite bounce arrow. Note shell uses flat borders `rgba(5,5,5,0.08)` and 8px radius — calm vs campaign.
- **Fix:** Re-style career navigation CTAs as standard Ant `Card` or ghost `Button` rows matching `note-layout__sider-header` vocabulary; drop gradients and bounce.
- **Suggested command:** `/impeccable polish careers and profile surfaces`

### [P1] Duplicate custom button system alongside Ant
- **Why it matters:** `MarkdownRenderer.css` and `NotePage.css` each define primary/secondary/complete buttons (6px radius, manual padding) while layout uses Ant `Button`, `Segmented`, `Modal`. Same actions, different heights, shadows, and dark-mode hex blocks duplicated twice.
- **Fix:** Replace custom completion/header buttons with Ant `Button` variants (`type="primary"`, `type="default"`, `type="primary" danger/success`) or one shared `.btn` module fed by tokens.
- **Suggested command:** `/impeccable polish note page buttons`

### [P2] Motion vocabulary is inconsistent and decorative in careers
- **Why it matters:** Impeccable/DESIGN.md: functional motion, 150–250ms, ease-out, no bounce. Found: `1.6s ease-in-out infinite` bounce on careers/profile; `transition: all` in `NoteLayout.css`, mindmap nodes; durations 0.15–0.3s mixed; `ease` generic instead of ease-out-quart.
- **Fix:** Standardize `--duration-fast: 150ms`, `--duration-normal: 200ms`, `--ease-out: cubic-bezier(...)`; replace bounce with one-shot translate on hover only; ban `transition: all`.
- **Suggested command:** `/impeccable animate careers profile note layout`

### [P2] Spacing off the 8px system
- **Why it matters:** DESIGN.md specifies 8px grid. Pervasive `gap: 10px` in assistant workspace, note header tools, layout assistant mode; career CTAs use `padding: 22px 20px 28px`; profile folder tabs `padding: 12px 28px`. Layout uses 16/24 correctly in places but 10px leaks everywhere.
- **Fix:** Audit gaps/padding to 4/8/16/24/32; replace 10px with 8 or 12 intentionally.
- **Suggested command:** `/impeccable layout src/common`

### [P2] Border-radius scale fragmented
- **Why it matters:** Tokens should be 6–8px per DESIGN.md. In use: 6, 8, 10, 12, 14, 16, 999px across cards, quotes, career cards, micro-course pill. Career cards at 14–16px feel softer than note tool cards at 8px.
- **Fix:** `--radius-sm: 6px`, `--radius-md: 8px`, `--radius-lg: 12px`; reserve 999px for true chips only.
- **Suggested command:** `/impeccable extract border-radius tokens`
