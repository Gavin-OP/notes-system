## Anti-Patterns Verdict

**LLM assessment:** The note reader is competent markdown infrastructure wrapped in prototype chrome. It reads closer to "Ant Design note viewer + AI assistant demo" than the calm study environment PRODUCT.md and DESIGN.md describe. The biggest tells: a stub home page, disclaimer as default entry, exposed Assistant Mode A/B UI, purple gradient CTA, and a right dock optimized for Q&A/Quiz instead of structure (outline, concepts, next step). Not full AI-slop, but the assistant-forward layout and dev-facing controls signal "feature sandbox" rather than "structured learning system."

**Deterministic scan (5 warnings in `src/`):**
- `side-tab` ×2: `AssistantWorkspace.css:129` (`border-left: 3px solid #722ed1`), `UserProfilePage.css:107`
- `layout-transition`: `MindmapView.css:82` (`transition: width`)
- `bounce-easing` ×2: `ExploreCareersPage.css:47`, `UserProfilePage.css:481`

Additional LLM catches not in CLI scan: purple-blue gradient on `note-page__micro-course-btn`, hard-coded `#722ed1` / `#1677ff` outside tokens.

**Visual overlays:** Injection succeeded on the disclaimer note. Overlays flagged: Roboto dominance (92%), flat type hierarchy, cramped padding on the page title, low contrast on "Mark as completed". These align with the header-tool clutter on the data-science intro note.

## Overall Impression

Solid reading engine and sidebar progress markers hint at the right product — but the shell still optimizes for AI tooling and internal experiments instead of **showing the map first**. A cross-disciplinary learner cannot answer "where am I in the field?" or "what should I learn next?" from the primary note layout. Replacing the home stub and building a real subject overview would shift the product identity immediately.

## What's Working

1. **Sidebar course sequence with progress markers** — Vertical timeline dots and completion coloring in `NoteLayout` give a calm, curriculum-like path without gamification. Matches DESIGN.md's learning-path guidance.
2. **Markdown reading surface** — Long-form notes with learning objectives, concept links, and heading structure render well; content quality supports the "teach from the outside in" principle.
3. **Search modal architecture** — `SearchModal` supports API highlights, local fallback, and typed result labels; foundation is there once search becomes visible and first-class.

## Priority Issues

### [P0] Home and default routing are not a learning entry point
- **Why it matters:** PRODUCT.md MVP requires subject catalog, continue learning, progress summary, and search entry. `HomePage` is a single "go to note system" button; `*` routes to it. New users never see the product promise.
- **Fix:** Replace `HomePage` with learner home: subject catalog, continue/resume, recommended first note, compact search. Route `/` to home; deep-link notes from there.
- **Suggested command:** `/impeccable craft learner home`

### [P0] No subject overview / learning path surface
- **Why it matters:** Core differentiation is structure before content. `SubjectEntry` is an empty outlet; learners jump from folder list straight into notes with no curriculum map, prerequisites, time estimates, or graph preview.
- **Fix:** Build subject page per DESIGN.md: overview, Start/Continue CTA, learning path timeline, graph entry, key concepts.
- **Suggested command:** `/impeccable shape subject overview page`

### [P1] Assistant Mode dev UI ships in the reading layout
- **Why it matters:** "Option 1: Right Dock / Option 2: Typeless" reads as internal QA, breaks trust ("Be simple enough to trust"), and adds extraneous load above every note.
- **Fix:** Remove or hide behind feature flag; pick one assistant presentation; use product labels if settings remain.
- **Suggested command:** `/impeccable distill note layout chrome`

### [P1] Forced seven-step product tour on first visit
- **Why it matters:** Blocks reading within seconds; contradicts calm, low-cognitive-load DESIGN.md and Jordan persona needs. Career pillar gets equal weight to structure in step 1 though career is "Could have."
- **Fix:** Optional "Take a tour" from help icon; shorten to 2–3 context steps or progressive hints on empty states.
- **Suggested command:** `/impeccable onboard note layout`

### [P1] Note header tool sprawl corrupts the reading hierarchy
- **Why it matters:** H1 accessibility name includes "Mark as completed", Mindmap, version select, and restore highlights — screen readers and visual hierarchy both suffer. Duplicate completion buttons in header and footer.
- **Fix:** Separate page meta bar from article title; one completion control; move version/highlight tools to overflow or profile/admin.
- **Suggested command:** `/impeccable layout note page header`

### [P1] Right panel prioritizes AI over structure
- **Why it matters:** DESIGN.md specifies right rail for in-note outline, concepts, and next steps. Default dock tab is outline but assistant Q&A/Quiz/Notes compete; no "Recommended next" or prerequisite chips.
- **Fix:** Default right rail: Outline + Core concepts + Recommended next; tuck assistant behind "Ask" entry per "AI should feel invisible until useful."
- **Suggested command:** `/impeccable shape note right rail`

### [P2] Search is hidden behind icon-only affordance
- **Why it matters:** DESIGN.md and PRODUCT.md call search visible and dependable; Google-inspired IA expects a top search bar.
- **Fix:** Persistent search field in header on desktop; full-width on mobile; keep modal for advanced results.
- **Suggested command:** `/impeccable clarify search entry`

## Minor Observations

- `index.css` still has Vite template body centering — may affect non-layout pages.
- Hard-coded purple (`#722ed1`) appears in assistant/profile side-tabs and micro-course gradient — conflicts with "one primary accent" and anti-purple-gradient rules.
