# LeetCode

LeetCode 不只包含算法，也可以直接练习 SQL。是否需要这条分支，先看目标岗位的 JD、在线测试与面试说明。“秋招都要刷题”听起来声势浩大，实际还是具体岗位说了算。

## 先判断岗位会考什么

数据分析、BI 和部分产品分析岗位更常见 SQL、数据处理与业务问题；软件开发和算法岗位可能涉及数据结构、算法、复杂度与现场编码；有些岗位只需要 take-home project 或案例，并不以 LeetCode 为主。

可以从招聘官网、邀请邮件、宣讲会和可信的近期面试反馈确认形式。题型确定后再练，进步会比漫无目的刷题更容易被看见。

## SQL 路线

LeetCode 官方的 [SQL 50 Study Plan](https://leetcode.com/studyplan/top-sql-50/)覆盖基础到中等题目。练习时可以按能力逐层展开：

- SELECT、WHERE、排序与条件表达；
- 聚合、GROUP BY 与 HAVING；
- INNER / LEFT JOIN 与多表关系；
- 子查询与 Common Table Expression；
- 日期、字符串和空值处理；
- 窗口函数、排名与移动计算。

每道题通过后，再问自己：表之间是什么关系、为什么选择这个 Join、重复行从哪里来、空值会怎样影响结果、有没有更清楚的写法。面试里能解释逻辑，和查询通过同样重要。

## 算法与数据结构路线

软件岗位可以从数组、字符串、哈希表、双指针、栈队列、链表、二叉树和图等基础模式开始，再根据目标岗位加入搜索、动态规划或更专门的题型。

[Top Interview 150](https://leetcode.com/studyplan/top-interview-150/)是 LeetCode 官方的综合面试计划，但它更像题型地图，不是所有人都需要完整走完。先找岗位高频模式与自己的薄弱点，会更轻。

## 一道题怎样真正变成自己的能力

可以保留这几项记录：

- 最初怎样理解题目；
- 第一个思路为什么可行或不可行；
- 最终使用了什么模式；
- 时间与空间复杂度，或 SQL 的执行逻辑；
- 容易错的边界、空值或重复数据；
- 过一段时间能否不看答案重做。

看懂题解是理解的开始，自己重新推出来才会逐渐变成稳定能力。错题按“读题、知识、实现、边界、时间”分类，也更容易发现真正卡点。

## 从独立练习过渡到面试表达

练习口头说明：先复述问题和假设，再讲基础方案、优化思路、复杂度和测试用例。写代码过程中持续解释关键判断，遇到卡点也让面试官知道你正在验证什么。

SQL 面试可以主动说明表结构、唯一键、NULL 与重复记录假设。算法题完成后，用正常、边界和异常输入走一遍。清楚沟通会让解题能力更完整。

## 建立可持续的节奏

基础题、错题回看、计时练习和模拟面试可以交替出现。状态不好时复习旧题也算前进；连续做新题却不回顾，容易产生“看过很多、临场想不起”的感觉。

面试复盘若反复指出某类缺口，再调整练习重点。LeetCode 是帮助进入目标岗位的工具，不需要变成衡量自己聪不聪明的排行榜。
