# Technical Interview

Technical Interview 不只存在於程序員招聘。數據、金融、工程、研究、設計和產品崗位，都可能用代碼題、案例、系統設計、專業知識或作品講解確認你的基礎與思考方式。

## 先確認到底考什麼

查看 JD、邀請郵件和公司官方説明，確認形式、時長、可用工具以及是否需要共享屏幕。相同崗位名稱在不同團隊裏，考察內容也可能完全不同。範圍不清楚時，可以向招聘聯繫人禮貌詢問。

## 回答時讓思路可見

拿到問題後，可以先複述目標、澄清假設，再講基礎方案和取捨。寫代碼或計算時，把關鍵判斷説出來；案例題則説明信息缺口、分析框架和優先級。面試官通常既在看結果，也在看你怎樣抵達結果。

## 遇到不會的問題

可以這樣處理：

1. 説明自己對問題的理解；
2. 確認邊界或舉一個小例子；
3. 從已知部分開始推導；
4. 講出會如何驗證；
5. 如果確實不瞭解，誠實説明邊界。

“我現在不確定，但我會先檢查……”通常比沉默或硬編更能展示工作方式。

## 常見準備材料

- JD 中反覆出現的知識與工具；
- 自己簡歷、項目集或 GitHub 中寫過的每個技術點；
- 基礎概念、典型題型和容易混淆的邊界；
- 能解釋取捨、失敗和改進的項目案例；
- 正常、邊界和異常測試思路。

## 結束前

如果答案中做了重要假設，可以在結尾補充。反問時可瞭解團隊技術棧、代碼或研究評審方式、新人支持和真實技術挑戰，讓這場面試也幫助你判斷崗位。
