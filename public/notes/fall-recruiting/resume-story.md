# 简历打磨与经历表达

简历就像你职业故事的“预告片”，它要快速回答三个核心问题：你做了什么，你贡献了什么，以及因为你，事情发生了什么变化。一份有说服力的简历，能让招聘者在短时间内看到你的潜力与价值。

<a id="concept-job-description-mapping"></a>
## 拆解 JD，与自己的经历进行匹配

在开始写简历前，先仔细阅读目标岗位的 Job Description (JD)。把它拆解成三类信息，帮助你找到最相关的经历：

-   **工作内容：** 入职后实际要解决什么问题？需要完成哪些任务？
-   **能力要求：** 岗位对技术、分析、沟通、协作或语言能力有什么具体要求？
-   **组织语境：** 公司强调哪些价值观 (Values)、使命 (Missions) 和工作方式？

看到核心要求时，可以问自己：“我的哪段经历和它有关？”
如果 JD 中提到的某些关键词，你还暂时没有与它们相匹配的经历，可以先留待日后发展，避免硬塞进简历。

一份简历很难同时照顾所有岗位。你可以根据岗位要求准备不同版本，调整经历的顺序、篇幅和表达重点。在文件名或岗位追踪表中标清每一份简历的侧重点和用途，会更容易管理。

如果你的几段实习或项目来自不同公司和行业，可以尝试找到贯穿其中的核心能力，比如分析问题、理解用户、推动产品、快速学习和跨团队沟通。看似零散的经历，往往也藏着一条很有个人特点的主线。

## 打造有说服力的经历描述

本节重点在于调整信息顺序与表达方式，但经历本身仍须真实。让你的简历能回应“公司文化 + JD”：

-   留意公司文化与 JD 反复强调的关键词。
-   为重要关键词找到真实经历或行为证据。
-   把相关证据提前，把关联较弱的细节压缩。
-   确保每点都能自然引导出你乐于回答的追问。

例如，如果岗位重视“沟通能力 (communication skills)”，那么“和谁沟通、遇到什么难点、怎样推进、最后发生了什么”会比简单一句“沟通能力强”更有画面感和说服力。

<a id="concept-star-evidence"></a>
### 整理可复用的 STAR 故事

一条完整且有力的经历描述，通常可以遵循 STAR 原则：Situation (情境)、Task (任务)、Action (行动) 和 Result (结果)。重点放在你的判断与行动，以及带来的具体影响。


**弱表达：**

> 参与用户调研，负责整理数据。

**更强表达：**

> 设计并执行 18 位用户访谈，将反馈归纳为 4 类关键问题，推动团队调整 onboarding 流程，提升了新用户转化率 15%。

在描述中，优先使用具体、有力的动词，并尽可能量化你的成果。量化成果时，每个数字都应来源清楚、口径可解释并提供必要背景，而非仅是堆砌。同时，清晰区分团队成果与个人贡献，突显你在团队中的独特价值。

为使每个故事更完整，可考虑补充以下两点：

-   **Reflection (反思)：** 如果重来一次，你会怎样改进？学到了什么？
-   **Role relevance (岗位关联)：** 这段经历为什么与当前岗位有关？它如何证明你具备岗位所需的能力？

建立能代表自己的故事库。可从快速学习、主动推进、处理分歧、团队协作、应对失败或不确定性等主题取材。一个故事完全可以回答不同问题，只需跟着问题调整重点和侧重。

## 格式、版本与 ATS 友好

一份专业的简历，内容与呈现方式同样重要。

-   **ATS 友好：** 许多公司使用 Applicant Tracking System (ATS) 来初步筛选简历。为确保 ATS 有效识别，请使用标准标题（如“教育背景”、“工作经历”）、清晰段落结构，并避免复杂图表、图片或非常规字体。确保关键词可被解析，但避免过度堆砌。
-   **格式一致性：** 保持字体大小、行距、项目符号及整体版面的一致性。确保所有链接（如 LinkedIn 个人主页、个人作品集）皆可点击。
-   **文件类型：** 除非招聘方另有要求，请一律导出为 PDF 格式。PDF 能保留排版，避免在不同设备上显示错乱。
-   **版本管理：** 针对不同岗位定制的简历，务必在文件名中清晰标注（例如“姓名_岗位名称_公司名_简历.pdf”），以便管理。
-   **最终检查：** 除了内容，请仔细检查日期、时态、标点、错别字及不必要的行业术语。请朋友、同学或职业顾问协助审阅，他们可能发现你忽略的细节。
