# 个人主页

个人主页是一个稳定入口，用来集中呈现你的方向、经历、项目和联系方式。它不等于项目集：项目集深入讲作品，个人主页负责把简历、LinkedIn、GitHub、文章和项目组织到同一个地方。

## 什么时候值得做

如果内容分散在多个平台、简历放不下，或者岗位会关注作品、写作、技术实现与个人表达，个人主页会很有帮助。如果目前只有简历和一个项目，先把内容写好也完全可以，网站不是求职入场券。

## 首页先回答几个简单问题

招聘者快速浏览时，最好能看懂：

- 你是谁，目前关注什么方向；
- 最值得看的经历或项目是什么；
- 你的能力有什么证据；
- 怎样查看简历或联系你。

首页可以由简短介绍、代表项目、经历摘要、简历入口和联系方式组成。其他内容再按需要进入独立页面。

## 把信息层级放在视觉效果前面

每个项目先写一句结论，再给图片和详情链接。导航名称保持直白，例如 About、Projects、Experience、Writing、Contact。动画、3D 和复杂滚动如果会拖慢加载或挡住内容，就失去了帮助表达的意义。

手机是很重要的检查场景。文字能否舒适阅读、按钮是否容易点击、图片是否溢出、导航是否能关闭，都比炫酷效果更影响真实体验。

## 选择适合自己的搭建方式

- **Notion / 文档型页面：** 上手快，适合先整理内容；
- **网站生成器：** 拖拽完成，适合更自由的排版；
- **AI / Vibe Coding：** 用自然语言生成并反复调整，适合愿意尝试的人；
- **GitHub Pages：** 适合静态网站，官方提供从仓库发布的免费路径。

工具可以随时更换，内容结构才是长期资产。先做一个能分享的版本，再根据真实反馈调整，会比一直停在“选框架”更轻松。

## 可信与安全同样重要

- 公开邮箱可以使用专门的求职邮箱；
- 简历下载版删除不需要公开的住址、电话或证件信息；
- 项目数据先确认权限并脱敏；
- 外部链接使用清楚的文字，定期检查是否失效；
- 自定义域名、HTTPS 和访问统计都属于可选项；
- 不要在网页代码中放 API Key、密码或私密文件。

## 发布前做一次真实走查

在手机和电脑上各打开一次，从首页进入项目、简历和联系方式；再把链接发给朋友，请对方说出他认为你的方向和代表项目。如果理解与你期待不同，调整首页顺序和文案通常比继续增加页面更有效。

如果选择 GitHub Pages，可以参考 [GitHub 官方 Quickstart](https://docs.github.com/en/pages/quickstart)。它支持从仓库分支发布静态网站，也适合以后逐步更新。
