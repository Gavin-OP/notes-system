# 个人主页

个人主页是你专业身份的稳定入口，用来集中呈现你的方向、经历、项目和联系方式。它不同于项目集：项目集深入展示作品，而个人主页则负责把你的简历、LinkedIn、GitHub、文章和项目组织到同一个地方，提供一个全面的概览。

## 什么时候值得做

如果你的内容分散在多个平台、简历放不下，或者你申请的岗位特别关注作品、写作、技术实现与个人表达，那么个人主页会非常有帮助。如果目前你只有一份简历和一个项目，先把这些内容打磨好也完全可以，网站不是求职的强制入场券。

## 首页核心要素

当招聘者快速浏览你的网站时，最好能一眼看懂：
*   你是谁，目前关注什么方向；
*   最值得看的经历或代表项目是什么；
*   你的能力有什么证据；
*   怎样查看简历或联系你。

首页可以由简短介绍、代表项目、经历摘要、简历入口和联系方式组成。其他更详细的内容再按需进入独立的页面。

## 优先信息层级与可访问性

请将信息层级的重要性放在视觉效果之前。每个项目先写一句结论，再提供图片和详情链接。导航名称保持直白，例如 About、Projects、Experience、Writing、Contact。动画、3D 效果和复杂滚动若拖慢加载速度或遮挡内容，反而会妨碍信息传达。

移动端适配至关重要。文字能否舒适阅读、按钮是否容易点击、图片是否溢出、导航是否能顺畅开关，这些都比炫酷效果更能影响真实的用户体验。同时，为确保网站对所有用户都易于访问，请考虑使用语义化的 HTML、为图片添加替代文本（alt text），并确保足够的颜色对比度。

## 选择适合自己的搭建方式

工具可以随时更换，内容结构才是你长期的资产。先做一个能分享的版本，再根据真实反馈调整，会比一直停在“选框架”更轻松。

*   **Notion / 文档型页面：** 上手快，适合先整理内容；
*   **网站生成器（如 Squarespace, Webflow）：** 拖拽式操作，适合更灵活的排版；
*   **AI / Vibe Coding：** 用自然语言生成并反复调整，适合愿意尝试新方法的人；
*   **GitHub Pages：** 适合静态网站，官方提供从仓库发布的免费路径。

## 可信、隐私与安全

*   公开邮箱可以使用专门的求职邮箱，避免泄露私人信息；
*   简历下载版删除不需要公开的住址、电话或证件信息；
*   分享项目数据前，务必确认权限并进行脱敏处理，避免泄露机密；
*   外部链接使用清楚的文字描述，并定期检查是否失效；
*   自定义域名、HTTPS 加密和访问统计均为可选，但能显著提升专业度和安全性；
*   切勿在网页代码中直接放置 API Key、密码或私密文件。

## 发布前检查与维护

发布前，请进行一次彻底的检查。在手机和电脑上分别测试，从首页导航至项目、简历和联系方式。随后，将链接分享给朋友，请他们描述你网站传达的方向和代表项目。如果他们的理解与你期待的不同，调整首页的顺序和文案通常比继续增加页面更有效。

保持网站内容的时效性。一个内容准确、维护良好的小型网站，其影响力远超华丽却被遗弃或过时的网站。定期检查失效链接，并更新你的内容。

如果选择 GitHub Pages，可以参考 [GitHub 官方 Quickstart](https://docs.github.com/en/pages/quickstart)。它支持从仓库分支发布静态网站，也适合以后逐步更新。

## 首页层级预览

把你的首页想象成一场对话。访问者应该首先理解什么？排列这些元素，看看哪些会出现在“首屏”区域，以便快速浏览。

- **身份：** 你是谁？（例如：“产品设计师”，“专注于 AI 的软件工程师”）
- **方向：** 你关注什么或寻求什么？（例如：“构建直观的用户体验”，“解决复杂的数据问题”）
- **证据：** 你最强的证明。 （例如：“精选项目”，“关键成就”）
- **联系：** 如何联系你。 （例如：“LinkedIn”，“电子邮件”，“简历”）

*思考一下最能快速讲述你故事的顺序。*
