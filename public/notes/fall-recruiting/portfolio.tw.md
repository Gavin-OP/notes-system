# 項目集 (Portfolio)

項目集是簡歷的有力補充，它能承載簡歷放不下的作品、分析過程、設計決策、文案、代碼、實驗或項目細節。它不僅僅是作品的堆砌，而是一組精心挑選的工作樣本，旨在向招聘者展示你如何理解問題、做出取捨並最終達成結果。

## 何時使用項目集

首先，查看崗位描述（JD）是否提到 Portfolio、Work Sample、GitHub、Case Study 或 Project Experience。設計、產品、研究、數據、軟件、內容與諮詢類崗位尤其能從工作樣本中受益。對於不需要查看作品的崗位，準備好在面試當中清晰闡述你做過的項目，就已經足夠了。

## 如何選擇項目

選擇項目時，關鍵在於**相關性**和**可解釋性**。代表項目可以來自課程、實習、比賽、個人探索或社團。可以關注以下幾點：

*   它是否回應目標崗位會遇到的問題；
*   你的個人貢獻能否清晰闡明；
*   是否有過程、取捨和結果可以展示；
*   內容能否合法、合規地公開。

**精選而非堆砌：** 少量高質量、解釋清晰的項目，遠比大量缺乏背景的堆砌更具説服力。確保最能體現你能力的項目容易被看見。

## 處理保密信息與團隊項目

**保密信息：** 如果你的工作涉及公司數據、用户資料、專有代碼或保密協議（NDA），**絕不能未經許可直接發佈**。你可以使用脱敏數據、重建示例、只描述方法或展示高層級概念。拿不準時，務必先徵得許可。

**團隊項目：** 清晰呈現團隊背景和項目整體情況，同時精確定義你在其中負責的範圍和具體貢獻。

## 將每個項目構建為案例分析

將每個項目構建為一篇**案例分析（Case Study）**，這能讓招聘者快速理解你的思考過程和解決問題的能力。一個結構良好的案例通常包含以下要素：

1.  **問題與目標：** 你要解決什麼問題？目標是什麼？
2.  **背景與限制：** 用户、業務、時間、數據或資源等條件。
3.  **你的角色與貢獻：** 你負責哪些環節？與誰協作？具體做了什麼？
4.  **過程與選擇：** 你如何研究、分析、設計方案、迭代？為什麼做出這些選擇？
5.  **結果與證據：** 你的工作帶來了什麼？用數據、反饋、上線情況或學到的經驗來證明。
6.  **復盤與展望：** 如果繼續做，你會如何調整或改進？

為圖片、圖表、代碼和原型都配上簡要解釋。招聘者通常快速瀏覽，因此請先給出結論和個人貢獻，再引導感興趣的人深入細節。

## 用可視化幫助招聘者快速理解項目

項目集中的 Visualization，重點是幫助招聘者快速理解你面對的問題、解決過程、判斷和結果。圖片、圖表、原型和流程圖都應該承擔明確的信息功能，而不是單純作為裝飾。

### 可以優先展示這些內容

- **結果與關鍵指標：** 如果項目有明確結果，可以用數字卡片、前後對比、趨勢圖或簡單圖表突出最重要的變化，例如轉化率提升、效率改善、用户增長或性能變化。
- **過程與思考：** 用户旅程、流程圖、架構圖、研究框架、優先級矩陣等，都可以幫助招聘者快速理解你是怎樣分析問題和做出決策的。
- **最終產出：** 產品界面、Dashboard、設計稿、代碼片段、報告頁面或實際成果截圖，可以直觀證明你完成了什麼。
- **關鍵證據：** 用户反饋、實驗結果、數據分析、測試結果等，可以放在對應結論旁邊，幫助讀者理解你的判斷依據。

### 每張圖都應該回答一個問題

放入一張圖之前，可以先明確它希望招聘者看懂什麼。例如：

- **留存曲線：** 用户主要在哪個階段流失？
- **用户旅程地圖：** 用户在哪些步驟遇到了問題？
- **系統架構圖：** 這個項目的技術方案是怎樣組織的？
- **改版前後對比：** 你的方案帶來了什麼變化？
- **原型圖：** 最終方案如何解決前面發現的問題？

如果一張圖需要讀者花很長時間研究才能理解，可以進一步簡化，或者補充標題和説明。

### 圖表旁邊直接寫出你的發現

儘量避免只展示完整 Dashboard 或一整頁分析結果。可以在最重要的數據旁邊補一句具體結論，例如：

> 註冊後第 1–3 天是用户流失最明顯的階段，因此後續優化重點放在新用户首次體驗。

或者：

> 簡化投遞流程後，平均操作步驟從 6 步減少到 3 步，投遞完成率隨之提升。

這樣招聘者即使只快速瀏覽，也能理解這張圖為什麼值得看。

### 控制每個頁面的信息密度

一個案例中不需要展示所有分析過程。可以優先保留：

**背景與問題 → 關鍵分析或過程 → 你的決策 → 最終方案 → 結果**

同一種信息儘量只保留最有代表性的幾張圖。例如，做過十幾張分析圖，可以選出真正影響決策的兩三張，再把完整分析放進 GitHub、附錄或獨立 Dashboard。

### 讓可視化本身也具備可讀性

發佈前可以檢查：

- 圖表標題是否直接説明內容；
- 座標、單位、圖例和時間範圍是否清楚；
- 字號是否在普通筆記本屏幕上也能閲讀；
- 顏色是否承擔明確含義；
- 截圖中是否包含無關菜單、瀏覽器欄或大量空白；
- 重要區域是否可以通過裁剪、標註或放大突出；
- 每張圖附近是否能看到背景、你的貢獻或最終結論。

## 針對不同崗位調整項目集重點

你的項目集側重點應根據目標崗位而調整：

| 方向         | 更值得展示                                           |
| :----------- | :--------------------------------------------------- |
| 數據分析     | 問題定義、數據處理、SQL、指標、圖表與業務建議      |
| 產品         | 用户問題、需求判斷、優先級、方案取捨與結果         |
| 軟件開發     | 架構、核心實現、代碼質量、測試、部署與技術權衡     |
| 設計         | 研究、信息架構、迭代過程、可用性與視覺系統         |
| 諮詢/商業分析 | 問題拆解、假設、分析框架、洞察與建議               |
| 內容/市場    | 受眾、策略、創作過程、渠道數據與復盤               |

## 選擇呈現形式並確保可訪問性

**呈現形式：**

*   **PDF：** 適合發送和麪試展示。
*   **Notion/在線文檔：** 適合快速組織案例，易於更新。
*   **GitHub：** 最適合代碼、詳細的 README 和版本記錄。
*   **個人網站：** 作為統一入口，展示更全面的專業身份。

無需追求“高級”工具，穩定、清晰、手機可讀且鏈接有效的項目集，本身就已足夠專業。**務必在手機、平板和電腦等設備上測試所有鏈接和可讀性。**

## 審閲與優化你的項目集

發送前，可以請一個不瞭解項目的人快速瀏覽，然後問：TA 能否説出你解決的問題、你的貢獻和最終結果？如果答案模糊，應優先調整信息層級，而非繼續增加裝飾。

## 與其他平台整合

你精心準備的項目集可以同時放進簡歷、LinkedIn 和個人主頁。LinkedIn 官方也允許在 Profile 中加入 Projects 和媒體鏈接，確保你的作品在多個觸點都能被看見。
