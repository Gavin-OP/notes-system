# 項目集

如果你有想展示、但簡歷放不下的作品、分析過程或項目細節，項目集正好可以接住它們。它不是課程作業倉庫，而是一組經過選擇的工作樣本：讓招聘者看見你怎樣理解問題、做出取捨並完成結果。

## 先確認項目集是否適合這個崗位

設計、產品、研究、數據、軟件、內容與諮詢類崗位，常常能從工作樣本中受益。對於不需要查看作品的崗位，簡潔的項目鏈接可能已經足夠。先看 JD 是否提到 Portfolio、Work Sample、GitHub、Case Study 或 Project Experience，再決定投入深度。

## 選項目時看“相關性”和“可解釋性”

代表項目可以來自課程、實習、比賽、個人探索或社團。比起項目名有多厲害，更重要的是：

- 它是否回應目標崗位會遇到的問題；
- 你的個人貢獻能否單獨講清楚；
- 是否有過程、取捨和結果可以展示；
- 內容能否合法、合規地公開。

團隊項目可以呈現團隊背景，同時明確自己的範圍。涉及公司數據、用户資料、代碼或保密協議時，使用脱敏數據、重建示例或只描述方法；拿不準就先徵得許可。

## 把每個項目寫成一篇 Case Study

一個好瀏覽的項目通常包含：

1. **一句話摘要：** 解決了什麼問題，最終產出了什麼；
2. **背景與限制：** 用户、業務、時間、數據或資源條件；
3. **你的角色：** 負責哪些環節，與誰協作；
4. **過程與選擇：** 研究、分析、方案、迭代，以及為什麼這樣做；
5. **結果與證據：** 指標、反饋、上線情況或學到什麼；
6. **復盤：** 如果繼續做，會怎樣調整。

圖片、圖表、代碼和原型旁邊都配一句解釋。招聘者可能只快速瀏覽，先給結論和個人貢獻，再讓感興趣的人進入細節。

## 不同崗位展示的重點不同

| 方向 | 更值得展示 |
| --- | --- |
| 數據分析 | 問題定義、數據處理、SQL、指標、圖表與業務建議 |
| 產品 | 用户問題、需求判斷、優先級、方案取捨與結果 |
| 軟件開發 | 架構、核心實現、代碼質量、測試、部署與技術權衡 |
| 設計 | 研究、信息架構、迭代過程、可用性與視覺系統 |
| 諮詢/商業分析 | 問題拆解、假設、分析框架、洞察與建議 |
| 內容/市場 | 受眾、策略、創作過程、渠道數據與復盤 |

## 選擇最省力的呈現形式

PDF 適合發送和麪試展示；Notion 適合快速組織案例；GitHub 適合代碼、README 和版本記錄；個人網站適合建立統一入口。工具不需要“高級”，穩定、清楚、手機可讀、鏈接能打開，就已經很專業。

發送前可以請一個不瞭解項目的人快速瀏覽，然後問：他能否説出問題、你的貢獻和結果？如果答案模糊，優先改信息層級，而不是繼續加裝飾。

LinkedIn 官方也允許在 Profile 中加入 Projects 和媒體鏈接；已經做好的項目集可以同時放進簡歷、LinkedIn 和個人主頁，讓同一份內容在不同入口被看見。
