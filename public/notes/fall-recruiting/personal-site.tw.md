# 個人主頁

個人主頁是你專業身份的穩定入口，用來集中呈現你的方向、經歷、項目和聯繫方式。它不同於項目集：項目集深入展示作品，而個人主頁則負責把你的簡歷、LinkedIn、GitHub、文章和項目組織到同一個地方，提供一個全面的概覽。

## 什麼時候值得做

如果你的內容分散在多個平台、簡歷放不下，或者你申請的職位特別關注作品、寫作、技術實現與個人表達，那麼個人主頁會非常有幫助。如果目前你只有一份簡歷和一個項目，先把這些內容打磨好也完全可以，網站不是求職的強制入場券。

## 首頁核心要素

當招聘者快速瀏覽你的網站時，最好能一眼看懂：
*   你是誰，目前關注什麼方向；
*   最值得看的經歷或代表項目是什麼；
*   你的能力有什麼證據；
*   怎樣查看簡歷或聯繫你。

首頁可以由簡短介紹、代表項目、經歷摘要、簡歷入口和聯繫方式組成。其他更詳細的內容再按需進入獨立的頁面。

## 優先資訊層級與可訪問性

請將資訊層級的重要性放在視覺效果之前。每個項目先寫一句結論，再提供圖片和詳情連結。導航名稱保持直白，例如 About、Projects、Experience、Writing、Contact。動畫、3D 效果和複雜滾動若拖慢加載速度或遮擋內容，反而會妨礙資訊傳達。

行動裝置適配至關重要。文字能否舒適閱讀、按鈕是否容易點擊、圖片是否溢出、導航是否能順暢開關，這些都比炫酷效果更能影響真實的用戶體驗。同時，為確保網站對所有用戶都易於訪問，請考慮使用語義化的 HTML、為圖片添加替代文本（alt text），並確保足夠的顏色對比度。

## 選擇適合自己的搭建方式

工具可以隨時更換，內容結構才是你長期的資產。先做一個能分享的版本，再根據真實回饋調整，會比一直停在“選框架”更輕鬆。

*   **Notion / 文件型頁面：** 上手快，適合先整理內容；
*   **網站生成器（如 Squarespace, Webflow）：** 拖曳式操作，適合更靈活的排版；
*   **AI / Vibe Coding：** 用自然語言生成並反覆調整，適合願意嘗試新方法的人；
*   **GitHub Pages：** 適合靜態網站，官方提供從倉庫發佈的免費路徑。

## 可信、隱私與安全

*   公開郵箱可以使用專門的求職郵箱，避免洩露私人資訊；
*   簡歷下載版刪除不需要公開的住址、電話或證件資訊；
*   分享項目數據前，務必確認權限並進行脫敏處理，避免洩露機密；
*   外部連結使用清楚的文字描述，並定期檢查是否失效；
*   自定義域名、HTTPS 加密和訪問統計均為可選，但能顯著提升專業度和安全性；
*   切勿在網頁代碼中直接放置 API Key、密碼或私密文件。

## 發佈前檢查與維護

發佈前，請進行一次徹底的檢查。在手機和電腦上分別測試，從首頁導航至項目、簡歷和聯繫方式。隨後，將連結分享給朋友，請他們描述你網站傳達的方向和代表項目。如果他們的理解與你期待的不同，調整首頁的順序和文案通常比繼續增加頁面更有效。

保持網站內容的時效性。一個內容準確、維護良好的小型網站，其影響力遠超華麗卻被遺棄或過時的網站。定期檢查失效連結，並更新你的內容。

如果選擇 GitHub Pages，可以參考 [GitHub 官方 Quickstart](https://docs.github.com/en/pages/quickstart)。它支持從倉庫分支發佈靜態網站，也適合以後逐步更新。

## 首頁層級預覽

把你的首頁想像成一場對話。訪問者應該首先理解什麼？排列這些元素，看看哪些會出現在“首屏”區域，以便快速瀏覽。

- **身份：** 你是誰？（例如：“產品設計師”，“專注於 AI 的軟體工程師”）
- **方向：** 你關注什麼或尋求什麼？（例如：“建構直觀的使用者體驗”，“解決複雜的數據問題”）
- **證據：** 你最強的證明。 （例如：“精選項目”，“關鍵成就”）
- **聯繫：** 如何聯繫你。 （例如：“LinkedIn”，“電子郵件”，“簡歷”）

*思考一下最能快速講述你故事的順序。*
