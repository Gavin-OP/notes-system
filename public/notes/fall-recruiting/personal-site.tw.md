# 個人主頁

個人主頁是一個穩定入口，用來集中呈現你的方向、經歷、項目和聯繫方式。它不等於項目集：項目集深入講作品，個人主頁負責把簡歷、LinkedIn、GitHub、文章和項目組織到同一個地方。

## 什麼時候值得做

如果內容分散在多個平台、簡歷放不下，或者崗位會關注作品、寫作、技術實現與個人表達，個人主頁會很有幫助。如果目前只有簡歷和一個項目，先把內容寫好也完全可以，網站不是求職入場券。

## 首頁先回答幾個簡單問題

招聘者快速瀏覽時，最好能看懂：

- 你是誰，目前關注什麼方向；
- 最值得看的經歷或項目是什麼；
- 你的能力有什麼證據；
- 怎樣查看簡歷或聯繫你。

首頁可以由簡短介紹、代表項目、經歷摘要、簡歷入口和聯繫方式組成。其他內容再按需要進入獨立頁面。

## 把信息層級放在視覺效果前面

每個項目先寫一句結論，再給圖片和詳情鏈接。導航名稱保持直白，例如 About、Projects、Experience、Writing、Contact。動畫、3D 和複雜滾動如果會拖慢加載或擋住內容，就失去了幫助表達的意義。

手機是很重要的檢查場景。文字能否舒適閲讀、按鈕是否容易點擊、圖片是否溢出、導航是否能關閉，都比炫酷效果更影響真實體驗。

## 選擇適合自己的搭建方式

- **Notion / 文檔型頁面：** 上手快，適合先整理內容；
- **網站生成器：** 拖拽完成，適合更自由的排版；
- **AI / Vibe Coding：** 用自然語言生成並反覆調整，適合願意嘗試的人；
- **GitHub Pages：** 適合靜態網站，官方提供從倉庫發佈的免費路徑。

工具可以隨時更換，內容結構才是長期資產。先做一個能分享的版本，再根據真實反饋調整，會比一直停在“選框架”更輕鬆。

## 可信與安全同樣重要

- 公開郵箱可以使用專門的求職郵箱；
- 簡歷下載版刪除不需要公開的住址、電話或證件信息；
- 項目數據先確認權限並脱敏；
- 外部鏈接使用清楚的文字，定期檢查是否失效；
- 自定義域名、HTTPS 和訪問統計都屬於可選項；
- 不要在網頁代碼中放 API Key、密碼或私密文件。

## 發佈前做一次真實走查

在手機和電腦上各打開一次，從首頁進入項目、簡歷和聯繫方式；再把鏈接發給朋友，請對方説出他認為你的方向和代表項目。如果理解與你期待不同，調整首頁順序和文案通常比繼續增加頁面更有效。

如果選擇 GitHub Pages，可以參考 [GitHub 官方 Quickstart](https://docs.github.com/en/pages/quickstart)。它支持從倉庫分支發佈靜態網站，也適合以後逐步更新。
