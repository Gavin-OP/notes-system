# 用 AI 辅助找岗位

这一节不是教编程，而是带你用自然语言做一个只服务自己的岗位查找与整理工具。开始前先判断它是否值得：工具的意义是减少重复搜索和比较，不是为秋招再开一个耗时的新项目。

## 先判断要不要自己做

更适合自己做的情况：

- 同时关注多种岗位名，平台筛选经常漏掉相关职位；
- 需要反复比较 JD、截止时间和准备要求；
- 现有表格已经越来越难搜索；
- 愿意花一点时间测试，并接受第一版很简单。

继续使用平台提醒和表格可能更合适的情况：

- 目标公司和岗位已经很明确；
- 目前更缺简历、投递或面试准备时间；
- 希望自动抓取所有招聘网站，但不想处理登录、反爬、条款和数据维护；
- 做工具本身开始比找岗位更占精力。

一个简单判断是：如果它不能替你省下重复动作，也没有作为项目展示的价值，就先不做。

## 第一版只做一个浏览器里的岗位看板

为了让零编程基础也能完成，第一版采用静态网页，不连接招聘网站、不调用付费 API，也不需要后端。它可以：

- 手动添加岗位名称、公司、链接、地点、截止时间和备注；
- 按关键词、状态和标签筛选；
- 标记收藏、已投递、测试、面试和结束；
- 在浏览器本地保存，下次打开仍保留；
- 导出 JSON 或 CSV 备份。

这已经能解决“岗位散落在收藏夹里”和“忘记申请到哪一步”的问题。浏览器的 `localStorage` 会按网站保存数据，并能跨浏览器会话保留；它适合小型个人工具，但清理浏览器数据或更换设备时可能丢失，所以导出备份很重要。

## 选择一个可以对话生成网页的工具

可以使用 Replit Agent、Lovable 或其他你信任的 Vibe Coding 平台。界面会更新，核心流程都类似：创建项目、描述需求、预览、反馈修改、发布。

开始前留意套餐、公开范围和隐私设置。不要上传真实密码、证件、未公开公司材料或 API Key。岗位链接和个人备注如果比较敏感，可以只放在本地版本。

## 第一步：把需求完整交给 AI

创建一个新 Web App，把下面的 Prompt 复制进去：

> 请为零编程基础用户创建一个纯前端的个人岗位查找与申请管理工具。使用简洁、响应式的中文界面，不需要登录、数据库、后端或任何外部 API。用户可以手动新增岗位，字段包括公司、岗位名称、岗位链接、地点、来源、截止日期、标签、当前状态和备注。支持关键词搜索，按状态与标签筛选，按截止日期排序，标记收藏，并显示即将截止的岗位。所有数据保存在浏览器 localStorage。提供导出 JSON、导入 JSON 和导出 CSV，导入前提示不会自动上传任何数据。加入少量示例数据和清空示例按钮。请先列出实现计划，等我确认后再构建。

先看 AI 给出的计划。确认它没有加入账号、数据库、付费 API、自动爬虫或你不需要的复杂页面，再让它开始。

## 第二步：在预览里按真实流程测试

不要只看首页漂不漂亮。添加一个真实岗位，然后依次检查：

- 刷新页面后岗位是否仍在；
- 搜索公司或岗位关键词能否找到；
- 状态和标签能否修改；
- 截止时间为空时是否报错；
- 很长的岗位名在手机上是否溢出；
- 导出后能否重新导入；
- 删除是否有确认提示。

发现问题时，把“我做了什么、期待什么、实际发生什么”告诉 AI。例如：

> 我在手机预览中添加了一个很长的岗位名称，卡片超出屏幕。请只修复移动端文本换行和卡片宽度，不改变其他功能。修复后告诉我改了什么，并再次检查 375px 宽度。

一次只改一类问题，比“帮我全部优化”更容易得到稳定结果。

## 第三步：再加真正省时间的功能

基础版本稳定后，可以逐个加入：

- 从复制的一段 JD 中提取公司、职责、技能和截止日期，提取结果先让用户确认；
- 比较几个已保存 JD 的重复技能；
- 为不同岗位保存简历版本和 Cover Letter 链接；
- 显示每个招聘阶段的数量；
- 生成本周需要关注的截止事项。

如果这些功能需要调用 AI API，就会产生密钥管理、费用和隐私问题。最小版本可以继续保持纯本地，把“智能提取”留给以后。

## 第四步：发布或只留给自己

平台通常提供 Publish / Deploy 按钮。发布前确认仓库与网站是否公开，删除示例中的真实个人信息。也可以把静态文件放到 GitHub，再按 [GitHub Pages 官方 Quickstart](https://docs.github.com/en/pages/quickstart)从分支发布。

公开网站仍然只在当前浏览器保存数据：换设备不会自动同步。MDN 的 [Web Storage 说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)也提醒，隐私浏览结束后本地数据会被清除。工具里保留导入导出，能让这个限制更可控。

## 常见卡点怎么和 AI 说

- **它加了太多功能：** “回到纯前端 MVP，只保留岗位新增、筛选、状态、本地保存和导入导出。”
- **刷新后数据消失：** “请检查 localStorage 的保存与初始化，不要引入数据库。”
- **改一处坏一处：** “先说明根因，只做最小修复，并检查已有功能没有回归。”
- **页面手机上难用：** “请用移动端优先布局，按钮至少容易触控，表单改为单列，禁止横向滚动。”
- **不知道代码是否安全：** “列出所有外部请求、第三方包和会收集的数据；不要在前端保存任何密钥。”

Replit 的 [官方入门文档](https://docs.replit.com/build/your-first-app)也采用“描述范围—检查计划—预览测试—发布”的完整循环。会不会写代码不是这次练习的门槛，能否把问题说清楚、控制范围并认真测试，才是关键。
