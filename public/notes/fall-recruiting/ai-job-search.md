# 用 AI 辅助找岗位

本指南将带你用自然语言（与 AI 对话）搭建一个只服务于你自己的岗位查找与申请管理工具。开始前，请先判断它是否值得投入时间：工具应简化你的求职过程，而非增加一个耗时的新项目。

## 先判断要不要自己做

自己动手做一个工具，最重要的是它能真正解决问题，而非增加负担。

**更适合自己做的情况：**

*   **信息分散难管理：** 你同时关注多种岗位名或行业，现有平台筛选经常漏掉相关职位，或者你的岗位信息散落在多个收藏夹、截图和表格中，越来越难搜索和比较。
*   **需要深度对比：** 你需要反复比较不同岗位的职责描述（JD）、截止时间和准备要求，并希望记录下自己的思考和进展。
*   **现有工具不趁手：** 你已经在使用表格或简单的笔记工具，但它们在筛选、排序或标记状态方面已经力不从心。
*   **愿意投入测试：** 你愿意花一点时间测试工具的可用性，并接受第一版可能很简单，后续再逐步完善。
*   **有项目展示价值：** 这个小工具本身可以作为你解决问题、快速原型开发能力的展示。

**继续使用平台提醒和表格可能更合适的情况：**

*   **目标明确：** 你关注的目标公司和岗位已经很明确，数量不多，现有平台的提醒和简单的表格就能满足需求。
*   **时间紧迫：** 目前你更缺的是准备简历、投递申请或面试的时间，而不是整理岗位信息的时间。
*   **期望过高：** 你希望工具能自动抓取所有招聘网站的最新信息，但又不想处理登录、反爬机制、平台条款和数据维护的复杂问题。
*   **本末倒置：** 做工具本身开始比找岗位更占精力，让你偏离了求职主线。

一个简单的判断：如果它不能替你省下重复动作，也没有作为项目展示的价值，就先不做。求职的核心是匹配和沟通，工具只是辅助。

<note-interactive type="decision-aid" title="我该自己做吗？">
**如果你符合以下任一情况，可以考虑自己做：**
- 现有信息分散，平台筛选不准，或表格已无法满足需求。
- 需要反复对比岗位细节，记录思考和进展。
- 愿意投入少量时间测试和迭代，并接受 MVP 版本。
- 这个工具本身能作为你解决问题能力的展示。

**如果你符合以下任一情况，建议继续使用现有工具：**
- 目标明确，岗位数量不多，现有提醒和表格已足够。
- 时间紧迫，优先准备简历和面试。
- 期望自动抓取所有网站，但不想处理技术和合规问题。
- 制作工具已成为求职的负担。

## 第一版只做一个浏览器里的岗位看板

为了让零编程基础的用户也能完成，我们的第一版工具将采用纯前端静态网页的形式。这意味着它不连接招聘网站、不调用付费 API，也不需要后端服务器。所有数据都安全地保存在你的浏览器里。

**它可以实现以下核心功能：**

*   **手动添加岗位信息：** 轻松录入公司、岗位名称、岗位链接、地点、来源（如哪个招聘网站）、截止日期、自定义标签、当前状态（如“待申请”、“已投递”、“面试中”）和备注。
*   **灵活筛选与排序：** 支持按关键词搜索，按状态和标签进行多维度筛选，并按截止日期排序，让你一眼看到即将截止的岗位。
*   **可视化管理：** 标记收藏、已投递、测试、面试和结束等不同阶段，清晰掌握每个岗位的进展。
*   **本地数据保存：** 所有数据都保存在你当前浏览器的 `localStorage` 中，下次打开页面时数据依然保留。
*   **数据备份与迁移：** 提供导出 JSON、导入 JSON 和导出 CSV 的功能，方便你备份数据或在不同设备间迁移。导入前会明确提示，数据不会自动上传到任何地方。

这个最小可行产品（MVP）能有效解决岗位信息分散和忘记申请进度的常见问题。浏览器的 `localStorage` 会按网站保存数据，并能跨浏览器会话保留。它非常适合小型个人工具，但请注意，清理浏览器数据或更换设备时数据可能丢失，因此定期导出备份至关重要。

## 选择一个可以对话生成网页的工具

你可以使用 Replit Agent、Lovable，或任何你信任的对话式 AI 编程平台（即通过对话生成代码）。这类平台的界面可能会不断更新，但核心流程都类似：

1.  **创建项目：** 选择一个 Web App 或前端项目模板。
2.  **描述需求：** 用自然语言向 AI 详细描述你想要的功能。
3.  **预览与测试：** AI 生成代码后，在预览界面查看效果。
4.  **反馈修改：** 根据测试结果，向 AI 提出修改意见。
5.  **发布：** 满意后，将你的工具发布上线（或只保留在本地）。

**开始前，请留意以下几点：**

*   **套餐与公开范围：** 检查平台提供的免费套餐限制，以及你的项目默认是公开还是私有。
*   **隐私与安全：** **切勿**上传或在代码中硬编码真实的密码、证件号码、未公开的公司材料或任何 API Key。岗位链接和个人备注如果比较敏感，可以只在本地版本使用，避免发布到公开网站。

## 第一步：把需求完整交给 AI

创建一个新的 Web App 项目，然后复制以下 Prompt（提示词），它已包含我们 MVP 的所有核心需求：

> 请为零编程基础用户创建一个纯前端的个人岗位查找与申请管理工具。使用简洁、响应式的中文界面，不需要登录、数据库、后端或任何外部 API。用户可以手动新增岗位，字段包括公司、岗位名称、岗位链接、地点、来源、截止日期、标签、当前状态和备注。支持关键词搜索，按状态与标签筛选，按截止日期排序，标记收藏，并显示即将截止的岗位。所有数据保存在浏览器 localStorage。提供导出 JSON、导入 JSON 和导出 CSV，导入前提示不会自动上传任何数据。加入少量示例数据和清空示例按钮。请先列出实现计划，等我确认后再构建。

**在 AI 构建之前，请仔细查看它给出的实现计划。** 确认它没有擅自加入账号系统、数据库、付费 API、自动爬虫或任何你不需要的复杂页面。只有在你完全确认计划符合“纯前端、本地化、无复杂功能”原则后，再让它开始生成代码。

## 第二步：在预览里按真实流程测试

不要只看首页是否美观或功能列表是否完整。你需要像一个真正的用户一样，按照实际使用流程来测试。

**添加一个真实岗位，然后依次检查以下关键点：**

*   **数据持久性：** 刷新页面后，你添加的岗位信息是否仍然存在？
*   **搜索与筛选：** 搜索公司或岗位关键词能否准确找到？状态和标签能否正确修改和筛选？
*   **边界情况：** 截止时间为空时，页面是否报错或显示异常？很长的岗位名在手机预览中是否溢出屏幕？
*   **导入导出：** 导出数据后，能否成功重新导入？
*   **用户体验：** 删除岗位时是否有确认提示，避免误操作？

**发现问题时，把“我做了什么、期待什么、实际发生了什么”清晰地告诉 AI。** 例如：

> 我在手机预览中添加了一个很长的岗位名称，结果卡片超出了屏幕，导致内容显示不全。我期待它能在移动端自动换行并调整卡片宽度。请只修复移动端文本换行和卡片宽度的功能，不要改变其他功能。修复后请告诉我具体改了什么，并再次检查 375px 宽度下的显示效果。

一次只解决一类问题，并给出明确的修复范围，比笼统地要求“全部优化”更容易得到稳定和满意的结果。

## 第三步：再加真正省时间的功能

当你的基础版本稳定后，可以考虑逐个加入真正省时间的功能。但请记住，每增加一个功能，都要重新评估其价值、复杂度和潜在的隐私风险。

**你可以考虑的功能包括：**

*   **智能提取：** 从复制的一段岗位描述（JD）中自动提取公司、职责、技能和截止日期。提取结果应先让你确认，再保存。
*   **技能对比：** 比较几个已保存岗位的重复技能要求，帮助你发现共性或准备重点。
*   **简历版本管理：** 为不同岗位保存对应的简历版本和求职信（Cover Letter）链接。
*   **阶段统计：** 显示每个招聘阶段（如“已投递”、“面试中”）的岗位数量，让你对整体进展一目了然。
*   **截止事项提醒：** 生成本周需要关注的截止事项清单。

**隐私与成本提示：** 如果这些功能需要调用外部 AI API（例如用于更复杂的文本分析），就会产生密钥管理、费用支出和隐私数据传输的问题。在最小版本中，你可以继续保持纯本地运行，把“智能提取”等功能留给未来，或者只在本地手动使用 AI 工具辅助完成。

## 第四步：发布或只留给自己

大多数对话式 AI 编程平台都提供 Publish / Deploy（发布/部署）按钮。

**发布前请确认：**

*   **仓库与网站公开范围：** 你的代码仓库和部署后的网站是否是公开的？
*   **个人信息清理：** 确保你删除示例数据中任何真实的个人信息或敏感内容。

你也可以选择不发布到平台的公共域名，而是将生成的静态文件（HTML, CSS, JS）下载下来，然后放到你自己的 GitHub 仓库中，再按照 [GitHub Pages 官方 Quickstart](https://docs.github.com/en/pages/quickstart) 的指引，从特定分支发布成一个免费的静态网站。

**数据同步提醒：** 即使你的网站发布到线上，数据保存在浏览器的 `localStorage`，仍只在当前浏览器保存。这意味着更换设备后，数据不会自动同步。MDN 的 [Web Storage 说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API) 也提醒，使用隐私浏览模式结束后，本地数据会被清除。因此，工具中保留的导入导出功能，能让你更好地控制和管理数据，应对这些限制。

## 常见卡点怎么和 AI 说

在使用 AI 生成工具时，你可能会遇到一些常见问题。以下是一些有效的沟通方式：

*   **它加了太多功能：** “回到纯前端 MVP，只保留岗位新增、筛选、状态、本地保存和导入导出功能。”
*   **刷新后数据消失：** “请检查 `localStorage` 的保存与初始化逻辑，确保数据能持久化，不要引入数据库。”
*   **改一处坏一处：** “请先说明导致这个问题的根本原因，然后只做最小范围的修复，并检查已有功能没有出现新的问题（没有回归）。”
*   **页面手机上难用：** “请采用移动端优先的布局（Mobile-first design），确保按钮容易触控，表单元素改为单列显示，并禁止页面出现横向滚动条。”
*   **不知道代码是否安全：** “请列出所有外部请求、第三方依赖包和可能收集的数据；确保不要在前端代码中保存任何敏感密钥。”

Replit 的 [官方入门文档](https://docs.replit.com/build/your-first-app) 也采用了“描述范围—检查计划—预览测试—发布”的完整循环。编程技能不是这里的门槛；关键在于清晰地阐述问题、控制范围并认真测试。
