# 项目集

如果你有想展示、但简历放不下的作品、分析过程或项目细节，项目集正好可以接住它们。它不是课程作业仓库，而是一组经过选择的工作样本：让招聘者看见你怎样理解问题、做出取舍并完成结果。

## 先确认项目集是否适合这个岗位

设计、产品、研究、数据、软件、内容与咨询类岗位，常常能从工作样本中受益。对于不需要查看作品的岗位，简洁的项目链接可能已经足够。先看 JD 是否提到 Portfolio、Work Sample、GitHub、Case Study 或 Project Experience，再决定投入深度。

## 选项目时看“相关性”和“可解释性”

代表项目可以来自课程、实习、比赛、个人探索或社团。比起项目名有多厉害，更重要的是：

- 它是否回应目标岗位会遇到的问题；
- 你的个人贡献能否单独讲清楚；
- 是否有过程、取舍和结果可以展示；
- 内容能否合法、合规地公开。

团队项目可以呈现团队背景，同时明确自己的范围。涉及公司数据、用户资料、代码或保密协议时，使用脱敏数据、重建示例或只描述方法；拿不准就先征得许可。

## 把每个项目写成一篇 Case Study

一个好浏览的项目通常包含：

1. **一句话摘要：** 解决了什么问题，最终产出了什么；
2. **背景与限制：** 用户、业务、时间、数据或资源条件；
3. **你的角色：** 负责哪些环节，与谁协作；
4. **过程与选择：** 研究、分析、方案、迭代，以及为什么这样做；
5. **结果与证据：** 指标、反馈、上线情况或学到什么；
6. **复盘：** 如果继续做，会怎样调整。

图片、图表、代码和原型旁边都配一句解释。招聘者可能只快速浏览，先给结论和个人贡献，再让感兴趣的人进入细节。

## 不同岗位展示的重点不同

| 方向 | 更值得展示 |
| --- | --- |
| 数据分析 | 问题定义、数据处理、SQL、指标、图表与业务建议 |
| 产品 | 用户问题、需求判断、优先级、方案取舍与结果 |
| 软件开发 | 架构、核心实现、代码质量、测试、部署与技术权衡 |
| 设计 | 研究、信息架构、迭代过程、可用性与视觉系统 |
| 咨询/商业分析 | 问题拆解、假设、分析框架、洞察与建议 |
| 内容/市场 | 受众、策略、创作过程、渠道数据与复盘 |

## 选择最省力的呈现形式

PDF 适合发送和面试展示；Notion 适合快速组织案例；GitHub 适合代码、README 和版本记录；个人网站适合建立统一入口。工具不需要“高级”，稳定、清楚、手机可读、链接能打开，就已经很专业。

发送前可以请一个不了解项目的人快速浏览，然后问：他能否说出问题、你的贡献和结果？如果答案模糊，优先改信息层级，而不是继续加装饰。

LinkedIn 官方也允许在 Profile 中加入 Projects 和媒体链接；已经做好的项目集可以同时放进简历、LinkedIn 和个人主页，让同一份内容在不同入口被看见。
