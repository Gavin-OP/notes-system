# 用 AI 輔助找崗位

這一節不是教編程，而是帶你用自然語言做一個只服務自己的崗位查找與整理工具。開始前先判斷它是否值得：工具的意義是減少重複搜索和比較，不是為秋招再開一個耗時的新項目。

## 先判斷要不要自己做

更適合自己做的情況：

- 同時關注多種崗位名，平台篩選經常漏掉相關職位；
- 需要反覆比較 JD、截止時間和準備要求；
- 現有表格已經越來越難搜索；
- 願意花一點時間測試，並接受第一版很簡單。

繼續使用平台提醒和表格可能更合適的情況：

- 目標公司和崗位已經很明確；
- 目前更缺簡歷、投遞或面試準備時間；
- 希望自動抓取所有招聘網站，但不想處理登錄、反爬、條款和數據維護；
- 做工具本身開始比找崗位更佔精力。

一個簡單判斷是：如果它不能替你省下重複動作，也沒有作為項目展示的價值，就先不做。

## 第一版只做一個瀏覽器裏的崗位看板

為了讓零編程基礎也能完成，第一版採用靜態網頁，不連接招聘網站、不調用付費 API，也不需要後端。它可以：

- 手動添加崗位名稱、公司、鏈接、地點、截止時間和備註；
- 按關鍵詞、狀態和標籤篩選；
- 標記收藏、已投遞、測試、面試和結束；
- 在瀏覽器本地保存，下次打開仍保留；
- 導出 JSON 或 CSV 備份。

這已經能解決“崗位散落在收藏夾裏”和“忘記申請到哪一步”的問題。瀏覽器的 `localStorage` 會按網站保存數據，並能跨瀏覽器會話保留；它適合小型個人工具，但清理瀏覽器數據或更換設備時可能丟失，所以導出備份很重要。

## 選擇一個可以對話生成網頁的工具

可以使用 Replit Agent、Lovable 或其他你信任的 Vibe Coding 平台。界面會更新，核心流程都類似：創建項目、描述需求、預覽、反饋修改、發佈。

開始前留意套餐、公開範圍和隱私設置。不要上傳真實密碼、證件、未公開公司材料或 API Key。崗位鏈接和個人備註如果比較敏感，可以只放在本地版本。

## 第一步：把需求完整交給 AI

創建一個新 Web App，把下面的 Prompt 複製進去：

> 請為零編程基礎用户創建一個純前端的個人崗位查找與申請管理工具。使用簡潔、響應式的中文界面，不需要登錄、數據庫、後端或任何外部 API。用户可以手動新增崗位，字段包括公司、崗位名稱、崗位鏈接、地點、來源、截止日期、標籤、當前狀態和備註。支持關鍵詞搜索，按狀態與標籤篩選，按截止日期排序，標記收藏，並顯示即將截止的崗位。所有數據保存在瀏覽器 localStorage。提供導出 JSON、導入 JSON 和導出 CSV，導入前提示不會自動上傳任何數據。加入少量示例數據和清空示例按鈕。請先列出實現計劃，等我確認後再構建。

先看 AI 給出的計劃。確認它沒有加入賬號、數據庫、付費 API、自動爬蟲或你不需要的複雜頁面，再讓它開始。

## 第二步：在預覽裏按真實流程測試

不要只看首頁漂不漂亮。添加一個真實崗位，然後依次檢查：

- 刷新頁面後崗位是否仍在；
- 搜索公司或崗位關鍵詞能否找到；
- 狀態和標籤能否修改；
- 截止時間為空時是否報錯；
- 很長的崗位名在手機上是否溢出；
- 導出後能否重新導入；
- 刪除是否有確認提示。

發現問題時，把“我做了什麼、期待什麼、實際發生什麼”告訴 AI。例如：

> 我在手機預覽中添加了一個很長的崗位名稱，卡片超出屏幕。請只修復移動端文本換行和卡片寬度，不改變其他功能。修復後告訴我改了什麼，並再次檢查 375px 寬度。

一次只改一類問題，比“幫我全部優化”更容易得到穩定結果。

## 第三步：再加真正省時間的功能

基礎版本穩定後，可以逐個加入：

- 從複製的一段 JD 中提取公司、職責、技能和截止日期，提取結果先讓用户確認；
- 比較幾個已保存 JD 的重複技能；
- 為不同崗位保存簡歷版本和 Cover Letter 鏈接；
- 顯示每個招聘階段的數量；
- 生成本週需要關注的截止事項。

如果這些功能需要調用 AI API，就會產生密鑰管理、費用和隱私問題。最小版本可以繼續保持純本地，把“智能提取”留給以後。

## 第四步：發佈或只留給自己

平台通常提供 Publish / Deploy 按鈕。發佈前確認倉庫與網站是否公開，刪除示例中的真實個人信息。也可以把靜態文件放到 GitHub，再按 [GitHub Pages 官方 Quickstart](https://docs.github.com/en/pages/quickstart)從分支發佈。

公開網站仍然只在當前瀏覽器保存數據：換設備不會自動同步。MDN 的 [Web Storage 説明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)也提醒，隱私瀏覽結束後本地數據會被清除。工具裏保留導入導出，能讓這個限制更可控。

## 常見卡點怎麼和 AI 説

- **它加了太多功能：** “回到純前端 MVP，只保留崗位新增、篩選、狀態、本地保存和導入導出。”
- **刷新後數據消失：** “請檢查 localStorage 的保存與初始化，不要引入數據庫。”
- **改一處壞一處：** “先説明根因，只做最小修復，並檢查已有功能沒有迴歸。”
- **頁面手機上難用：** “請用移動端優先佈局，按鈕至少容易觸控，表單改為單列，禁止橫向滾動。”
- **不知道代碼是否安全：** “列出所有外部請求、第三方包和會收集的數據；不要在前端保存任何密鑰。”

Replit 的 [官方入門文檔](https://docs.replit.com/build/your-first-app)也採用“描述範圍—檢查計劃—預覽測試—發佈”的完整循環。會不會寫代碼不是這次練習的門檻，能否把問題説清楚、控制範圍並認真測試，才是關鍵。
