# LeetCode

LeetCode 不只包含算法，也可以直接練習 SQL。是否需要這條分支，先看目標崗位的 JD、在線測試與面試説明。“秋招都要刷題”聽起來聲勢浩大，實際還是具體崗位説了算。

## 先判斷崗位會考什麼

數據分析、BI 和部分產品分析崗位更常見 SQL、數據處理與業務問題；軟件開發和算法崗位可能涉及數據結構、算法、複雜度與現場編碼；有些崗位只需要 take-home project 或案例，並不以 LeetCode 為主。

可以從招聘官網、邀請郵件、宣講會和可信的近期面試反饋確認形式。題型確定後再練，進步會比漫無目的刷題更容易被看見。

## SQL 路線

LeetCode 官方的 [SQL 50 Study Plan](https://leetcode.com/studyplan/top-sql-50/)覆蓋基礎到中等題目。練習時可以按能力逐層展開：

- SELECT、WHERE、排序與條件表達；
- 聚合、GROUP BY 與 HAVING；
- INNER / LEFT JOIN 與多表關係；
- 子查詢與 Common Table Expression；
- 日期、字符串和空值處理；
- 窗口函數、排名與移動計算。

每道題通過後，再問自己：表之間是什麼關係、為什麼選擇這個 Join、重複行從哪裏來、空值會怎樣影響結果、有沒有更清楚的寫法。面試裏能解釋邏輯，和查詢通過同樣重要。

## 算法與數據結構路線

軟件崗位可以從數組、字符串、哈希表、雙指針、棧隊列、鏈表、二叉樹和圖等基礎模式開始，再根據目標崗位加入搜索、動態規劃或更專門的題型。

[Top Interview 150](https://leetcode.com/studyplan/top-interview-150/)是 LeetCode 官方的綜合面試計劃，但它更像題型地圖，不是所有人都需要完整走完。先找崗位高頻模式與自己的薄弱點，會更輕。

## 一道題怎樣真正變成自己的能力

可以保留這幾項記錄：

- 最初怎樣理解題目；
- 第一個思路為什麼可行或不可行；
- 最終使用了什麼模式；
- 時間與空間複雜度，或 SQL 的執行邏輯；
- 容易錯的邊界、空值或重複數據；
- 過一段時間能否不看答案重做。

看懂題解是理解的開始，自己重新推出來才會逐漸變成穩定能力。錯題按“讀題、知識、實現、邊界、時間”分類，也更容易發現真正卡點。

## 從獨立練習過渡到面試表達

練習口頭説明：先複述問題和假設，再講基礎方案、優化思路、複雜度和測試用例。寫代碼過程中持續解釋關鍵判斷，遇到卡點也讓面試官知道你正在驗證什麼。

SQL 面試可以主動説明表結構、唯一鍵、NULL 與重複記錄假設。算法題完成後，用正常、邊界和異常輸入走一遍。清楚溝通會讓解題能力更完整。

## 建立可持續的節奏

基礎題、錯題回看、計時練習和模擬面試可以交替出現。狀態不好時複習舊題也算前進；連續做新題卻不回顧，容易產生“看過很多、臨場想不起”的感覺。

面試復盤若反覆指出某類缺口，再調整練習重點。LeetCode 是幫助進入目標崗位的工具，不需要變成衡量自己聰不聰明的排行榜。
